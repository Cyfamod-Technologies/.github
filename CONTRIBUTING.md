# Contributing to Cyfamod Technologies

Thank you for considering a contribution. Cyfamod welcomes useful, respectful contributions to selected public projects from developers, designers, technical writers, testers, DevOps engineers and security practitioners.

## Before you begin

1. Read the target repository's README and any repository-specific contribution instructions.
2. Search existing issues and pull requests to avoid duplicated work.
3. For a substantial change, open or join an issue before implementation so maintainers and contributors can agree on scope.
4. Do not include credentials, customer data, private infrastructure details or other confidential information.

## Standard workflow

1. Fork the repository.
2. Create a focused branch from the repository's default branch.
3. Make the smallest coherent change that solves the agreed problem.
4. Add or update tests and documentation where appropriate.
5. Run the repository's format, lint, test and build commands.
6. Commit with a clear message.
7. Open a pull request using the provided template.

Suggested branch names:

```text
feat/short-description
fix/short-description
docs/short-description
chore/short-description
```

## Pull-request quality

A strong pull request:

- explains the problem and the chosen solution;
- links the relevant issue;
- stays focused and avoids unrelated refactors;
- includes screenshots for visible UI changes;
- describes testing performed;
- documents breaking changes, migrations or new configuration;
- contains no secrets, generated clutter or unrelated formatting changes.

## Review process

Maintainers may request changes, suggest a smaller scope or close work that does not align with the project direction. Review comments should focus on the contribution, remain respectful and explain the reason for requested changes.

## Security
